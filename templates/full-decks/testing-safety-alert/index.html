AI 가 틀렸을 때의 대가는 나쁜 답변 하나로 끝나지 않습니다. 한 번에 티켓 300건을 쓰고, PR 80개를 올리고, 메일 5,000통을 보낼 수 있습니다.

위험은 이미 규모를 얻었습니다

틀렸을 때의 비용도 × N, 맞았을 때의 이득도 × N.
그래서 테스트·검수·보안·리스크가 앞으로 3년간 가장 비싼 능력이 됩니다.

section · level taxonomy02 / 08
위험 등급 · 3 levels03 / 08

세 등급, 세 가지 대응

L1 · 초록

되돌릴 수 있음

초안 쓰기, 이미지 생성, 문서 기초.
틀리면 Ctrl+Z, 비용 0.
방침: 그냥 돌린다

L2 · 호박

일부만 되돌릴 수 있음

초안 메일 발송, PR 등록, staging 데이터 수정.
틀리면 사과하거나 롤백해야 합니다.
방침: 사람이 검토

L3 · 빨강

되돌릴 수 없음

실제 메일 발송, 결제, DB 삭제, prod 데이터 삭제.
틀리면 그걸로 끝입니다.
방침: 강제 차단 + 2인 승인

agent 가 스스로 등급을 올리게 두지 마세요

L1 작업이 스스로 L2 가 되어서는 안 됩니다. 권한은 명시적이고, 회수할 수 있고, 만료 시각이 있어야 합니다.

규칙은 문서가 아니라 코드로

YAML 서른 줄로
레드라인을 강제 차단

# safety-policy.yaml · compiled → runtime guard
level_1_allow:
  - tools: [write_draft, generate_image, read_docs]

level_2_require_review:
  - tools: [send_email_draft, open_pr, write_staging_db]
    reviewer: human

level_3_hard_block:
  - tools: [send_real_email, transfer_money, delete_prod]
    unless: two_human_sign_off AND within_24h

forbidden_always:
  - "rm -rf /"
  - "drop table"
  - "force push origin main"

✓

✓
프롬프트 주입으로 권한을 넘길 수 있나? (레드팀 문구를 돌려봤나)
!
개인정보를 다루나? 로그에도 개인정보가 남나?
✓

!

✓
틀렸을 때 즉시 멈출 수 있나? (kill switch 가 2초 안에 듣나)
!
