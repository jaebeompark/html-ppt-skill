deep-dive · 1 / 2

Future 에는 메서드가 사실 하나뿐입니다.

컴파일러는 async fn 을 Future 트레이트를 구현한 익명 상태 기계로 바꿉니다. 런타임이 하는 일은 하나뿐입니다 — Ready 가 나올 때까지 계속 poll 하는 것.

Pending Ready(T) Waker.wake()
future.rs
pub trait Future {
    type Output;
    fn poll(
        self: Pin<&mut Self>,
        cx: &mut Context<'_>,
    ) -> Poll<Self::Output>;
}

// Poll::Pending   → 보류. waker 가 깨울 때까지 대기
// Poll::Ready(v)  → 완료. v 를 내놓음

deep-dive · 2 / 2

Tokio 는 남의 일을 훔쳐 오는 일꾼입니다.

멀티스레드 런타임은 worker N 개입니다. 각자 자기 로컬 큐를 갖고, 한가해진 worker 는 남의 큐에서 작업을 "훔쳐" 옵니다.

✦ local queue · 256 slots
✦ global injection queue
✦ work-stealing @ 50% steal ratio
✦ LIFO slot for cache locality

scheduler tick loop

1. pop from LIFO slot
2. else pop from local queue
3. else drain global queue (every 61 ticks)
4. else steal from random victim
5. else park the thread

mini-runtime.rs · ~40 LOC

가장 작은 런타임을 직접 짜 봅니다.

src/main.rs
use std::collections::VecDeque;
use std::sync::{Arc, Mutex};
use std::task::{Context, Poll, Wake, Waker};

struct Task(Mutex<Pin<Box<dyn Future<Output = ()> + Send>>>);

impl Wake for Task {
    fn wake(self: Arc<Self>) { QUEUE.lock().unwrap().push_back(self); }
}

fn block_on<F: Future<Output = ()> + Send + 'static>(fut: F) {
    spawn(fut);
    while let Some(task) = QUEUE.lock().unwrap().pop_front() {
        let waker = Waker::from(task.clone());
        let mut cx = Context::from_waker(&waker);
        let mut fut = task.0.lock().unwrap();
        let _ = fut.as_mut().poll(&mut cx); // 핵심은 이 한 줄
    }
}

가져가실 세 가지.

1 · async 는 비용 없는 추상화

상태 기계로 컴파일됩니다. 런타임 가상 테이블도, GC 도 없습니다.

2 · Waker 가 맥박이다

Future 는 스스로 움직이지 않습니다. 언제 다시 poll 할지는 waker 가 정합니다.

3 · async 안에서 블로킹하지 말 것

std::fs::read 한 줄이 worker 하나를 통째로 멈춥니다. spawn_blocking 을 쓰세요.
